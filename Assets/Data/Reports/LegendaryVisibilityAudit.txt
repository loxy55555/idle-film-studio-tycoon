FASE 6.6 — Legendary Visibility Audit Report
=============================================
Date: 2026-06-10
Mode: READ-ONLY (no fixes applied)

DESIGN RULE (approved)
----------------------
Legendaries must be VISIBLE in collection but LOCKED until genre complete.
While locked:
  • NO real poster
  • NO real name
  • SHOW unlock condition only

CURRENT BEHAVIOR
----------------
Locked legendaries show FULL identity:
  • Real poster (dimmed, not hidden)
  • Real movieName
  • Rarity badge + genre info
  • Lock overlay + "BLOQUEADA" label + condition text ADDED on top

This leaks content and breaks collection progression mystery.

DISCOVERY / LOCK STATE
----------------------
Collection discovery:
  MovieCollectionService.IsDiscovered(cfg, completedKeys)
  Key match: cfg.name in completedMovieKeys (produced movies)
  File: Assets/Scripts/Core/MovieCollectionService.cs L42-50

Legendary presentation lock:
  CollectionCatalogModel.IsLegendaryPresentationLocked()
  True when ANY non-legendary in same genre is not discovered
  File: Assets/Scripts/UI/Collection/CollectionCatalogModel.cs L151-167

Entry flags at build:
  discovered      = IsDiscovered OR CollectionDebugState.RevealAll
  legendaryLocked = IsLegendaryPresentationLocked OR bypass if RevealAll
  File: CollectionCatalogModel.cs L85-96

Production lock (separate system, MovieButtonUI.IsLocked):
  City unlock, studio level, reputation, saga prerequisites
  Legendaries: unlockCityLevel typically 8
  Does NOT affect collection card rendering

Unlock condition copy:
  LocKeys.CollectionLegendaryLock
  "Completa todas las películas de este género para desbloquear esta película legendaria."
  File: Assets/Scripts/Localization/Loc.cs L140

EDGE CASE
---------
When legendaryLocked=false but discovered=false (genre complete, not yet produced):
  BuildLegendaryLabels shows REAL title + dimmed poster + rarity
  NO "BLOQUEADA" label, NO unlock condition
  File: CollectionMovieCardView.cs L106-119 (falls through both if branches)

DESIGN DOC CONFLICT
-------------------
CoreGameplayAudit.txt L139-155 documents current behavior as intentional:
  "legendarias bloqueadas (título + condición visibles)"
This CONFLICTS with approved FASE 6.6 rule (placeholder + condition only).

ROOT CAUSE (exact)
------------------
Collection UI implements TWO different UX models in the same component:

  Model A (non-legendary undiscovered):
    Silhouette + "???" — identity hidden

  Model B (legendary, including legendaryLocked):
    Real cfg.movieName + real poster via MoviePosterVisual.Apply
    Lock feedback = dim + overlay + text labels ONLY

There is NO code path applying Model A to locked legendaries.

Production UI (MovieButtonUI) treats lock as interaction gating only,
never masking identity fields.
