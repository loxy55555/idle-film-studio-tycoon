MODELO ARQUITECTÓNICO GENERAL
══════════════════════════════════════════════════════════════════════
El HUD usa un modelo de "escena baked-first":

  [EDITOR] StudioUIBuilder.Build()
         ↓
  [EDITOR] HudDefinitiveSceneBaker.Bake()
         ↓  (sets DefinitiveHudShell.appliedMigrationVersion = 3+)
  [SCENE]  MainGame.unity contiene jerarquía baked

  Al pulsar Play:
  [RUNTIME] DefinitiveHudBootstrap.Install()
    → HudBakedSceneRules.IsBaked()? = true
    → NO restructuración. Solo patches visuales.

  Si la escena NO está baked (ruta legacy):
  [RUNTIME] HudDefinitiveStructureBuilder.Apply()
    → Restructura los 5 paneles.
    → HudLayoutPass.Apply()
    → Baked in-memory — hasta que se use el editor builder.

C) SISTEMAS DUPLICADOS — DOS SISTEMAS CON LA MISMA RESPONSABILIDAD
══════════════════════════════════════════════════════════════════════

DUP-01: Sub-tab font/height — DOS patchers en conflicto
  Sistema A: HudLayoutPass.CompactSubTabBar()
    → font=11px, height=56px — apply en unbaked path (HudLayoutPassBootstrap)
  Sistema B: DefinitiveHudBootstrap.PatchStudioSubTabs()
    → font=13px bold, height=52px — apply en baked path

  VEREDICTO:
  En escena baked: solo B ejecuta → 13px bold, 52px. ✓
  En escena unbaked: A ejecuta, B no. → 11px, 56px. (diferente aspecto)
  Son paths mutuamente excluyentes → no hay conflicto real en ejecución,
  pero producen resultados distintos. Fuente de verdad BAKED = B (PatchStudioSubTabs).

DUP-02: GenreSelectionUI vs MovieCollectionUI.BuildL1GenreGrid()
  Sistema A (legacy): GenreSelectionUI — 10 portadas de género, scroll
  Sistema B (activo): MovieCollectionUI.BuildL1GenreGrid() — misma función

  VEREDICTO: B ha absorbido completamente a A.
  A es destruido en runtime por BuildAllLevels(). Fuente de verdad = B.

DUP-03: CollectionNavController vs MovieCollectionUI (nav interno)
  Sistema A (legacy): CollectionNavController — show/hide L1/L2
  Sistema B (activo): MovieCollectionUI ShowGenreGrid/ShowMovieGrid/ClosePopup

  VEREDICTO: B ha absorbido completamente a A. Fuente de verdad = B.

DUP-04: MovieGridUI vs MovieCollectionUI.BuildL2MovieGrid()
  Sistema A (legacy): MovieGridUI — grid procedural
  Sistema B (activo): MovieCollectionUI L2 — grid 3 cols + rarity sort

  VEREDICTO: B ha absorbido completamente a A. Fuente de verdad = B.

DUP-05: HudLayoutPass.EnsureStudioVisualStage() vs StudioVisualStage.Awake()
  Sistema A: HudLayoutPass (unbaked) — crea o renombra legacy "StudioScene"
  Sistema B: StudioVisualStage.Awake() — aplica layout, layers, fade overlay

  VEREDICTO: A prepara el objeto; B siempre ejecuta y aplica el estado real.
  No hay conflicto — A garantiza que el GO exista, B lo configura.
  En escena baked A no ejecuta, B aplica todo. ✓

DUP-06: BonificationsBarUI (editor-built vs self-built)
  Sistema A (editor): StudioUIBuilder crea labels SpeedVal, QualityVal etc.
  Sistema B (self-build): BonificationsBarUI.EnsureBuilt() detecta
    si los labels no están y construye sus propias celdas.

  VEREDICTO: si el builder corrió, A existe y B no construye nada nuevo.
  Si el builder no corrió (escena sin bake), B se auto-construye.
  Son complementarios. Fuente de verdad = las celdas en escena si existen;
  fallback = self-build.

DIAGNÓSTICO: POR QUÉ ALGUNAS MODIFICACIONES NO APARECEN
══════════════════════════════════════════════════════════════════════

1. "Cambié el sub-tab font y no veo cambio"
   → El builder fijó 11px. Pero PatchStudioSubTabs() corre después
     en escena baked y lo sobreescribe a 13px. Para cambiar la fuente
     de sub-tabs en baked scene: modificar PatchStudioSubTabs() o
     la constante en HudLayoutConstants.

2. "El fondo del Premios sigue siendo el antiguo"
   → AwardsPanelUI.EnsureBuilt() destruye TODO el contenido de escena
     en el primer Awake. Si ves el fondo antiguo, el componente no se
     está ejecutando (panel inactivo). En cuanto abres la pestaña el
     viejo contenido es destruido.

3. "La colección sigue mostrando la versión antigua"
   → Si el panel tiene hijos legacy (GenreSelectionUI, botones de filtro),
     son destruidos por BuildAllLevels() al primer OnEnable.
     Si siguen visibles: MovieCollectionUI._built está en true pero no
     llegó a limpiar por algún error anterior — solución: restart Play.

4. "La tienda aparece vacía"
   → EnsureStorePanel() añade el componente pero el panel puede estar
     inactivo cuando AddComponent ejecuta (tab no visible).
     StorePanelUI.Start() y Awake() son los triggers de respaldo.
     Si el panel nunca se activa, la tienda no se construye.

5. "Los departamentos siguen con tarjetas pequeñas"
   → El marcador de layout era v2. DepartmentMiniCardLayoutBuilder usa
     v3 desde 8.6A — las tarjetas se reconstruyen en runtime.
     Si no se ven cambios: DepartmentMiniCardUI no está en escena,
     o el componente no llama EnsurePremiumLayoutIfNeeded.

Nota: [DefaultExecutionOrder] no tiene efecto en static bootstraps
(RuntimeInitializeOnLoadMethod). El orden entre bootstraps es indefinido.

1. BeforeSceneLoad (static)
   └── MovieCatalogRuntime — carga catálogo de películas

2. AfterSceneLoad (static, orden indefinido)
   ├── StudioUIShellLayout.Bootstrap() — ancla TopBar/BottomNav
   ├── DefinitiveHudBootstrap.Install() — patches visuales baked
   │     ├── PatchBottomNavLabels() — "TIENDA" etc.
   │     ├── PatchTopBarSettingsButton() — "⚙"
   │     ├── EnsureBonificationsBar() — inyecta componente
   │     ├── EnsureStorePanel() — inyecta StorePanelUI
   │     ├── PatchStudioSubTabs() — 13px, 52px, expand
   │     └── HudNavigationCleanup.NormalizeBottomNav()
   ├── HudLayoutPassBootstrap.Run() — IsBaked=true → NO-OP
   ├── MovieTabShellBootstrap.Install() — DefinitiveHudShell existe → NO-OP
   ├── CityPanelUI.Bootstrap() — añade CityPanelUI si necesario
   ├── ContentSortBootstrap.Install() — sorters de dept/upgrades
   ├── MissionObjectiveUI.Bootstrap() — attach a MissionCard
   └── UiSafeCleanup.Run() — oculta placeholders

3. Awake (MonoBehaviour, por DefaultExecutionOrder)
   -200: StudioUIShellLayout.Awake() — anclas shell
   -155: CityPanelUI.Awake() — hide placeholder, BuildLayout
   -100: GameHub.Awake() — init systems
      0: HudSkinBootstrap.Awake() — skins
      0: StudioVisualStage.Awake() — layers, fade, theme
      0: BonificationsBarUI.Awake() — subscribe + EnsureBuilt
      0: StorePanelUI.Awake() — EnsureBuilt (if active)
      0: AwardsPanelUI.Awake() — EnsureBuilt (if active)
      0: MovieCollectionUI.Awake() — EnsureBuilt (if active)
      0: ProductionHudShell.Awake() — WireRefreshButton
      0: ContractsPanelUI.Awake() — AutoWire
      0: DepartmentMiniCardUI.Awake() × 10 — EnsurePremiumLayout
      0: MovieTabUI.Awake() — subscribe events
      0: TopBarUI.Awake() — AutoWire

4. Start
      0: StudioHubUI.Start() — wire tab buttons, ShowTab(0) [Estudio]
      0: ProductionHudShell.Start() — UpgradeProductionLayout()
      0: Todos los paneles: Bind → Refresh

5. GameHub.OnGameReady (después de Start)
   └── Todos los paneles: Bind, Refresh datos desde sistemas
