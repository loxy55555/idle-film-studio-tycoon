PROBLEM STATEMENT
-----------------
Epic and Legendary borders in the Collection UI appear to use the same
color, or rarities are rendered incorrectly.

SYSTEMS AUDITED
---------------
  CollectionMovieCardView.cs    — card builder (frame assignment)
  CollectionLegendaryVisual.cs  — legendary-specific frame/poster
  MovieRarityVisual.cs          — non-legendary frame colors + badges
  MovieButtonUI.cs              — production offer cards (same color system)
  MoviePosterVisual.cs          — poster only, no frame logic

NOT FOUND IN CODEBASE (requested but absent):
  RarityFrameProvider           — does not exist
  CardFrameVisual               — does not exist

All frames are Unity UI Image components tinted via Image.color.
No rarity-specific sprites are assigned anywhere in the frame pipeline.

EPIC vs LEGENDARY — SHARED VISUAL RESOURCES?
================================================================

FRAMES:
  Epic (collection):     rgb(0.72, 0.58, 0.18) @ 55% alpha
  Legendary locked:      rgb(0.62, 0.48, 0.14) @ 85% alpha
  Legendary unlocked:    rgb(0.92, 0.76, 0.18) @ 95% alpha

  All three are in the GOLD/YELLOW hue family (R > G > B, low blue).
  Epic @ 55% alpha on dark card background ≈ muted yellow border.
  Legendary locked @ 85% alpha ≈ similar muted gold — VISUALLY SIMILAR.

  Epic and Legendary DO NOT share the same code path or constant,
  but they DO share the same color family (gold/yellow), producing
  near-identical appearance especially Epic vs locked Legendary.

BADGES:
  Epic badge:       (1.00, 0.88, 0.45)
  Legendary badge:  (1.00, 0.82, 0.35)
  Delta: ΔG=0.06, ΔB=0.10 — barely distinguishable on screen.

SPRITES:
  No sprite assigned to any rarity frame in collection or production.
  frame.sprite is never set in MovieRarityVisual or CollectionLegendaryVisual.
  Visual differentiation relies 100% on Color tinting.

PRODUCTION UI (for reference — MovieButtonUI.cs L119):
  Legendary uses MovieRarityVisual.LegendaryDim (0.55, 0.38, 0.12)
  Epic uses EpicGold (0.72, 0.58, 0.18)
  Production UI has MORE differentiation than Collection legendary path.

================================================================
ROOT CAUSE — EXACT
================================================================

PRIMARY: Dual frame systems with overlapping gold palette

  Epic cards use MovieRarityVisual.EpicGold (L10, L24).
  Legendary cards use CollectionLegendaryVisual frame constants (L7-8)
  which are brighter/darker variants of the SAME gold hue.

  CollectionMovieCardView.cs L44-47 splits legendary to a separate visual
  system that was designed for "premium gold" treatment but converges
  chromatically with EpicGold at collection card scale.

SECONDARY: No sprite differentiation

  All frames are color-only Image tints. Without distinct border sprites,
  hue proximity between EpicGold and FrameGold* is the only differentiator.

TERTIARY: Badge text colors for Epic/Legendary nearly identical

  MovieRarityVisual.cs L33-34: both bright gold, Δ < 0.10 per channel.

NOT A DATA BUG:
  MovieConfig.rarity field is correctly read (cfg.rarity).
  Wrong-rarity rendering would require data error — not observed in code.
  CollectionCatalogModel passes correct MovieConfig to Build().
