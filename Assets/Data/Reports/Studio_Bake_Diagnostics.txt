================================================================================
RESPUESTAS DIRECTAS
================================================================================

¿Las cards visibles provienen del bake?
  SÍ. Todos los GameObjects MiniCard_* y DeptRow_* con sus LayoutElements
  están serializados en Assets/Scenes/MainGame.unity.
  Los valores 192 se leen directamente del archivo .unity en disco.

¿Se reconstruyen alguna vez en runtime?
  NO. DepartmentMiniCardUI.EnsurePremiumLayoutIfNeeded() detecta el marcador
  "DeptCardLayout_v3" (bakeado) y llama WireExisting(), que solo lee referencias
  de componentes existentes. Build() y NormalizeParentRowHeight() nunca se
  ejecutan durante el ciclo de vida normal de una escena bakeada.

¿Existe actualmente un camino para regenerarlas?
  SÍ, pero requiere una acción explícita del editor. Ver Sección 6.

¿Qué script es la única fuente de verdad real?
  DepartmentMiniCardLayoutBuilder.cs (CardHeight = 140 actualmente).
  Es la única fuente que controla los valores que se serializan cuando se bake,
  y los únicos valores que Build() aplica a la escena. El archivo .unity es
  una "fotografía congelada" del momento del último bake.

================================================================================
SECCIÓN 1 — QUIÉN ESCRIBIÓ ORIGINALMENTE LOS 192 px
================================================================================

Script original: DepartmentMiniCardLayoutBuilder.cs

Método responsable: Build(RectTransform card, Color badgeColor)
  Líneas críticas (con CardHeight = 192 en el momento del bake):
    cardLE.preferredWidth  = CardWidth;    // 172
    cardLE.preferredHeight = CardHeight;   // 192  ← serializado en .unity
    cardLE.minHeight       = CardHeight;   // 192  ← serializado en .unity
    NormalizeParentRowHeight(card);        // rowLE.preferredHeight = 192

Método secundario: NormalizeParentRowHeight(RectTransform card)
  Busca el LayoutElement del padre (la fila DeptRow_N) y escribe:
    rowLE.preferredHeight = CardHeight;    // 192  ← serializado en .unity
    rowLE.minHeight = CardHeight si > CardHeight  (no aplica aquí)

Llamado desde: StudioUIBuilder.BuildMiniCard()
  Cuando el editor ejecutó "IdleFilm / Build Studio UI" por última vez.

================================================================================
SECCIÓN 2 — MOMENTO DE SERIALIZACIÓN EN EL PIPELINE
================================================================================

La cadena exacta de llamadas cuando se ejecutó el builder la última vez:

  1. EDITOR: IdleFilm > Build Studio UI  (menú Unity)
     → StudioUIBuilder.Build()
         → BuildEstudioPanel(switcher)
             → BuildDeptGrid(panel)
                 → for cada dept (11 depts, 6 filas de 2):
                     BuildMiniCard(row, deptType, name, hex)
                         → DepartmentMiniCardLayoutBuilder.Build(card, color)
                             → cardLE.preferredHeight = 192   [CardHeight en ese momento]
                             → cardLE.minHeight       = 192
                             → NormalizeParentRowHeight(card) → rowLE.preferredHeight = 192
                         → Añade marcador "DeptCardLayout_v3" como hijo vacío
         → HudDefinitiveSceneBaker.Bake(switcher, mainHubUI)
             → HudDefinitiveStructureBuilder.Apply(...)
                 → ApplyEstudioLayout(estudio)
                     → (StudioSubTabBar y StudioHeader layout, no tocan cards)
     → EditorSceneManager.SaveScene(scene)  ← PUNTO DE SERIALIZACIÓN FINAL

  2. Unity serializa el estado completo del grafo de escena a MainGame.unity.
     Cada LayoutElement queda como un componente separado en el YAML.

  3. Desde ese momento, los valores 192 viven en el archivo .unity y no en
     ninguna variable en memoria hasta que se carga la escena.

SECCIÓN 4 — SI EL VALOR 192 EXISTE FÍSICAMENTE EN LA ESCENA BAKEADA
================================================================================

  SÍ, existe físicamente en el archivo .unity:
    Ruta: Assets/Scenes/MainGame.unity
    Tipo de archivo: YAML serializado de Unity (texto)
    Instancias de m_PreferredHeight: 192 → 17
    Instancias de m_MinHeight: 192       → 11

================================================================================
SECCIÓN 5 — SI EXISTE ALGÚN SISTEMA RUNTIME QUE VUELVA A APLICAR 192 px
================================================================================

SISTEMA 1: DepartmentMiniCardUI.EnsurePremiumLayoutIfNeeded()
  Llamado en: Awake() y OnGameReady()
  Flujo con escena bakeada:
    1. HasPremiumLayout(transform) → comprueba transform.Find("DeptCardLayout_v3")
    2. El marcador EXISTE en escena → devuelve TRUE
    3. LLAMADA: WireExisting(transform) — solo lee referencias existentes
    4. NO llama: DepartmentMiniCardLayoutBuilder.Build() ni NormalizeParentRowHeight()
    5. RESULTADO: los LE bakeados (192) no se tocan

  Flujo SIN escena bakeada (si el marcador no existiera):
    1. HasPremiumLayout() → FALSE
    2. Comprueba si existe HorizontalLayoutGroup (guard para layouts legacy)
    3. Si no existe: llama DepartmentMiniCardLayoutBuilder.Ensure(this, color)
       → Ensure() → Build()  →  APLICA CardHeight=140 a los LE  →  crea marcador
    4. RESULTADO: los LE se crearían/actualizarían al nuevo CardHeight

SISTEMA 2: DepartmentContentSorter.SortNow()
  Definido en: Assets/Scripts/UI/Hub/ContentSortBootstrap.cs
  Instalado por: ContentSortBootstrap.Install() (AfterSceneLoad)
  Hace: reordena cards por índice de sibling (unlocked primero)
  NO modifica ningún LayoutElement. No toca tamaños.

SISTEMA 3: NormalizeParentRowHeight() (dentro de Build)
  Flujo: solo se llama si Build() se llama.
  En escena bakeada: NUNCA se ejecuta.
  Contiene una condición extra: solo sobreescribe si rowLE.preferredHeight > CardHeight.
  Con CardHeight=140 actual: si la fila tiene 192, 192>140 → sí sobreescribiría.
  PERO solo si Build() se dispara, lo cual no ocurre con el marcador presente.

SISTEMA 4: HudLayoutPass.ApplyEstudioLayout() + EnsureStudioVisualStage()
  No tocan cards ni filas. Solo stage, header, tabBar, subContent.

SISTEMA 5: DefinitiveHudBootstrap.PatchStudioSubTabs()
  No toca cards ni filas. Solo el StudioSubTabBar.

CONCLUSIÓN: No existe ningún sistema runtime que re-aplique ni mantenga
los 192 px. Son valores inertes que viven en el .unity y se cargan en memoria
en el momento de LoadScene. No hay código que los proteja activamente.

================================================================================
SECCIÓN 6 — QUÉ MÉTODO HABRÍA QUE EJECUTAR PARA RECONSTRUIR CON NUEVOS VALORES
================================================================================

La reconstrucción puede hacerse por tres caminos:

─── CAMINO A: Re-bake completo del Editor ───────────────────────────────────

  Ejecutar en Unity Editor (sin Play Mode):
    Menú: IdleFilm > Build Studio UI

  Esto llama StudioUIBuilder.Build() que:
    1. Destruye toda la jerarquía de escena existente
    2. Reconstruye todo desde cero con CardHeight=140 actual
    3. Serializa el .unity con los nuevos valores
    4. Guarda la escena

  Resultado: TODOS los LayoutElements se actualizan a los valores actuales
  del código. Es el único método con garantía de estado limpio.

─── CAMINO B: Re-bake selectivo del Editor ──────────────────────────────────

  No existe un menú "Rebuild only dept cards". Habría que:
    1. Seleccionar manualmente los 11 MiniCard_* en el Hierarchy
    2. Ejecutar un editor script que llame DepartmentMiniCardLayoutBuilder.Build()
       para cada card seleccionada
    3. Guardar la escena

─── CAMINO C: Patch runtime (requiere modificación de código) ────────────────

  Para aplicar los nuevos valores sin re-bake, habría que añadir un patch
  en DefinitiveHudBootstrap.ApplyBakedSceneVisualPatches() que itere
  sobre los cards/filas y actualice sus LayoutElements directamente:

    Ejemplo conceptual (NO aplicado — solo diagnóstico):
      foreach (var card in Object.FindObjectsByType<DepartmentMiniCardUI>(...))
      {
          var le = card.GetComponent<LayoutElement>();
          if (le != null)
          {
              le.preferredHeight = DepartmentMiniCardLayoutBuilder.CardHeight;
              le.minHeight       = DepartmentMiniCardLayoutBuilder.CardHeight;
          }
          var rowLE = (card.transform.parent as RectTransform)?.GetComponent<LayoutElement>();
          if (rowLE != null) rowLE.preferredHeight = DepartmentMiniCardLayoutBuilder.CardHeight;
      }
      LayoutRebuilder.ForceRebuildLayoutImmediate(contentRT);

  Sin este patch o sin re-bake, CardHeight=140 en código no tiene ningún
  efecto en runtime mientras el marcador "DeptCardLayout_v3" exista.

─── CAMINO D: Eliminar el marcador del bake (fuerza WireExisting→Build) ──────

  Si se eliminara el GameObject "DeptCardLayout_v3" de cada card en la escena
  (Editor o runtime), HasPremiumLayout() devolvería false, y la próxima vez
  que DepartmentMiniCardUI.EnsurePremiumLayoutIfNeeded() se llamara, ejecutaría
  DepartmentMiniCardLayoutBuilder.Ensure() → Build() con CardHeight=140.
  Este camino es frágil porque el marcador también sirve para evitar rebuilds
  duplicados.
