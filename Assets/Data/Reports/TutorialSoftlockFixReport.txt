ROOT CAUSES CORRECTED
---------------------
1. PremiereSequenceController — silent abort on null overlay
   File   : Assets/Scripts/UI/Premiere/PremiereSequenceController.cs
   Old bug: PresentNext() cleared the queue and returned silently when
            _overlay == null, never firing OnPremiereDismissed.
            FtueController was waiting for that event and stayed blocked.
   Fix    : When _overlay == null after EnsureOverlay(), the method now
            explicitly fires:
              OnPremiereDismissed?.Invoke();
            before returning, so all listeners are notified.

2. FtueController — premiere dependency removed (fallback coroutine)
   File   : Assets/Scripts/FTUE/FtueController.cs
   Old bug: CompleteFtue() could only be reached via OnPremiereDismissed.
            If the premiere overlay was unavailable or never dismissed, FTUE
            remained stuck at FtueStep.FirstMovieComplete indefinitely.
   Fix    : CompleteFallbackRoutine is started as soon as the first movie
            completes. It completes FTUE via TryCompleteFtueFromFirstMovie()
            through three independent paths:
              a) premiere_unavailable  — overlay never appeared within
                 PremiereUnavailableGraceSeconds (1.5 s)
              b) premiere_ended        — overlay appeared and was dismissed
                 (IsPresenting flipped false)
              c) fallback_timeout      — safety net after
                 PremiereFallbackMaxWaitSeconds (120 s)

3. FtueController — step regression on reload
   File   : Assets/Scripts/FTUE/FtueController.cs + FtueState.cs
   Old bug: ResumeStep mapped FtueStep.FirstMovieComplete (3) back to
            StudioDuringProduction (2), creating an infinite reload loop.
   Fix    : ResumeStep now has an explicit branch for FirstMovieComplete:
              - If studio.CompletedMovieKeys.Count >= 1 → CompleteFtue()
                immediately (movie already done, no need to wait)
              - Otherwise → StartCompleteFallback() and hide overlay
            FtueState.ApplySave() was also updated to clamp only in the
            range [Welcome, FirstMovieComplete]; it no longer remaps step 3
            to step 2.

4. FtueController — strong one-movie guard
   File   : Assets/Scripts/FTUE/FtueController.cs
   Old bug: OnMovieCompleted checked CompletedMovieKeys.Count != 1 which
            could skip the FirstMovieComplete transition if a movie had been
            completed out of band before the FTUE started.
   Fix    : ShouldAutoComplete() is called at startup (OnGameReady). If any
            completed movies already exist when FTUE starts, FTUE is
            auto-completed with reason "auto_complete_profile" before the
            tutorial even begins.
